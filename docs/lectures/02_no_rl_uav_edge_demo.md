# Lecture 02: No-RL UAV Edge Service Demo

## Motivation

Before implementing Q-learning or PPO, we need a working non-learning baseline.
This lecture runs fixed policies in the same simulator that future RL agents
will use.

The goal is not to be optimal. The goal is to make the simulator observable.

## Scenario

One or more UAVs serve compute tasks generated by ground devices.

At every control step, each UAV chooses one discrete action:

```text
0      hover / keep current target
1..K   select one candidate task from the local candidate list
```

For a candidate limit \(K\), the discrete action space is:

\[
\mathcal{A} = \{0, 1, \ldots, K\}.
\]

The simulator then advances by `control_interval` seconds. During that time:

- UAV velocities are applied through the mobility handler;
- tasks can expire;
- UAVs can reach targets;
- new tasks can arrive;
- rewards and metrics are updated.

A compact per-step reward can be read as:

\[
r_t =
r_t^{\mathrm{success}}
+ r_t^{\mathrm{miss}}
+ r_t^{\mathrm{wait}}
+ r_t^{\mathrm{move}}.
\]

The no-RL policies do not optimize this expression directly; they simply expose
how the simulator translates task service, deadline misses, queueing, and
movement into measurable outcomes.

## Policies

The current no-RL policies are:

| Policy | Meaning |
| --- | --- |
| `hover` | Never select a task. Useful as a lower-bound sanity check. |
| `random` | Sample a discrete action uniformly. Useful as a stochastic baseline. |
| `nearest` | Select the candidate task with the smallest distance. |
| `edf` | Select the earliest-deadline candidate. |
| `slo-risk` | Select the candidate with the smallest estimated slack. |

For a policy \(\pi\), the empirical average return over \(N\) episodes is:

\[
\bar{G}(\pi) = \frac{1}{N}\sum_{i=1}^{N} G^{(i)}.
\]

## What To Learn From The Demo

The no-RL demo should answer:

- Does the environment reset deterministically under a seed?
- Do tasks accumulate if the policy does nothing?
- Do action masks match candidate availability?
- Do heuristic policies reduce pending tasks compared with `hover`?
- Are rewards aligned with service success, deadline misses, waiting, and movement?

If these answers are unclear, do not move to RL yet.

## Bridge To Q-learning

Q-learning will replace the rule-based policy function:

```text
policy(env, rng) -> actions
```

with:

```text
state_discretizer(observation, metrics) -> state
epsilon_greedy(Q[state], action_mask) -> actions
td_update(Q, transition)
```

The simulator, scenario, metrics, and trace format should remain recognizable.
